# 设备

应用只做收集、处理与分发：数值经规则与事件算出强度与波形后，向**所有已连接设备**同时下发，插件配置不选设备。设备唯一标识取蓝牙 MAC（设备侧固定，重连不变）。

## 设备与输出路径

- **设备通信** 应用通过内置中转服务（`DglabRelayServer`）与 DG-LAB APP 扫码配对后直接下发强度/波形/清除指令；郊狼 V3 设备可经蓝牙直连，蓝牙已连接时规则输出与波形发送优先走蓝牙。原先的 Python `Bridge.py` / `WebSocketCore.py` 通信层已移除。

## 扫描与链路管理（多链路）

蓝牙输出设备不再互相排斥：**任意数量的郊狼 / 负鼠可以同时在线**，每台各自维护连接状态、电量、强度回执与波形进度。

- **扫描入口唯一**：`CoyoteBleController` 只做发现与型号识别，扫描结果按 MAC 去重，同一个 MAC 只出现一行；行上带型号、支持程度三态与「已连接」标记。
- **链路管理独立**：`BleDeviceManager` 按识别出的型号为设备创建驱动实例——郊狼 `CoyoteBleDevice`、负鼠 `OpossumBleController`，实例以 MAC 为键登记（`LinkRegistry`）。型号未知或本版无驱动时拒绝连接并给出原因文本。
- **没有互斥**：连接一台设备不会断开任何其它设备；断开只销毁该 MAC 的实例并从登记表移除，其余设备的连接状态、电量与波形原样保留。设备自行掉线（断电、超距）时该实例一并注销，再点一次即重建链路。
- **单一评选、按设备取值**：界面上的连接状态 / 电量 / 强度 / 状态文案读的是**默认设备**的一份只读快照；全部已连接设备（MAC、型号、电量、连接序号）由 `ble.connectedLinks` 给出，设备管理页据此逐台展示与断开。
- **输入设备（爪印 / 灵猫）同样按 MAC 多实例**：扫描入口把型号识别结果交给 `BleDeviceManager::open_input_link()`，每台设备一个驱动实例并按 MAC 登记；断开（或设备自行掉线）时 `close_input_link()` 销毁该实例，其它输入设备保持连接。它们不参与输出链路与默认设备评选，但计入「已连接设备 ×N」的蓝牙链路数。
- **每台输入设备一份数值模块**：模块名按实例生成 `paw_<MAC 后四位>` / `civet_<MAC 后四位>`（如 `paw_430C`），同型号多台各自一份数值与内置事件声明，互不覆盖；MAC 后四位撞车时追加序号（`paw_430C_2`、`paw_430C_3`…）并记一条 WARN 日志，实例显示名形如「爪印 430C」。

扫描结果按型号标注三态：**已支持**、**实验性**（驱动已实现，行可点选连接）、**暂不支持**（行不可点击）。实验性设备首次连接成功会弹一次「此设备连接为实验性，功能未经完整验证」，是否已提示记在 `app.devices.<MAC>.experimental_notice_shown`。

### 型号识别顺序

型号按「MAC 记忆 → 蓝牙名」两级识别，记忆优先于名称:

1. 该 MAC 记忆的型号（`app.devices.<MAC>.model`）命中型号表 → 按该型号的状态处理（郊狼即「已支持」，不弹实验性提示）；操作系统只交付占位名（`Bluetooth <mac>`）的郊狼靠这一级恢复「已支持」；
2. 否则蓝牙名命中 `47L1` 型号表 → 用表里的型号、显示名与支持程度；
3. 其它 `47L1` 前缀（未登记型号）→ 不支持，行内提示「未登记的 DG-LAB 型号」；
4. 非 `47L1` 前缀（手机、耳机、手环等）→ 不支持，行内提示「非 DG-LAB 设备」。

名称与记忆冲突时以记忆为准。首次成功识别出型号时写回记忆（来源可以是名称命中，也可以是下面的首帧反推）。

连接后若型号仍未识别，按通知帧首字节反推一次：`B1` 郊狼、`B3` 负鼠、`51` / `5A` / `5B` / `5C` 爪印；`D0` 在爪印与灵猫之间歧义，只记一条调试日志、不写记忆。反推只在未识别出型号时进行，不覆盖型号表与已有记忆，冲突时以记忆为准并记一次日志。

爪印与灵猫是纯输入设备，只上报数值与事件，不参与输出，也不参与默认设备评选。

## 设备管理页

左侧导航「设备管理」（`AppBridge::Page::DevicePage`，`pages/DevicePage.qml`）是蓝牙相关操作的唯一界面入口，设置页不再有蓝牙控件。四张卡：

- **扫描**：`deviceScanButton` → `CoyoteBleController::startScan()`；结果按 MAC 一行，显示蓝牙名、MAC、型号、支持状态三态与原因，行尾按钮在这台设备上切换「连接」/「断开」——判定用 `CoyoteBleController::has_link(address)`，连接走既有的 `connectDevice(address)`，断开走新增的 `disconnectDeviceByAddress(address)`（只销毁该 MAC 的实例）。
- **已连接设备**：`ble.connectedLinks` 的逐台明细（MAC / 型号 / 电量 / 连接序号），每行一个「断开」，同样按 MAC 断开，其它设备保持原状。
- **默认设备**：下拉只列在线输出设备（`device.outputDevices`），选中即写 `app.output.default_device`；同卡提供默认设备的 A/B 强度增减，与迷你窗同一入口。
- **通道上限与安全上限**：先选设备再分别编辑 A / B 的上限与安全上限，写入与回读见下一节；界面显示当前生效值 `min(上限, 安全上限)`，未设置的通道标「默认」。

## 默认设备

默认设备只在**有输出能力**的设备之间评选，与在线台数无关（1 台与多台用同一套规则）:

- `app.output.default_device` 非空且该设备在线时用它；
- 否则自动评选，顺序为「郊狼 > 负鼠 > 其它，同类型先连接者优先」（「先连接」按设备实例的连接序号，重连后重新发号）；
- 没有在线输出设备时没有默认设备。

评选实现只有一份：`pick_default_device()`（`include/ble/BleDeviceManager.h`），`DeviceController::default_output()` 与 `ble` 快照都用它，界面与下发不会出现两套口径。

用户主动断开或掉线的设备只会离开在线集合，因此自动回到自动评选，配置键保留。首页看板的下拉是切换入口（只列在线输出设备），迷你窗、看板强度 / 波形与事件波形下发都以默认设备为目标；默认设备变更时停止旧波形并重发当前强度。每通道还可用 `app.output.<A|B>.target` 指定输出目标，为第二台输出设备预留路由。

## 每设备通道上下限

上下限的读取只有一条链、集中在 `DeviceController::limits_for(mac, channel)`:

1. `app.devices.<MAC>.{limit_a, safety_a, limit_b, safety_b}`
2. `app.channels.<A|B>.{limit, safety}`
3. 内置默认：`limit = 200` / `safety = 150`

界面显示与下发都用这条链算出的 `min(limit, safety)`，切换默认设备后立即跟随。通道级键是全局配置，所有插件共用。

写入入口只有一处：设备管理页「通道上限与安全上限」卡（`DeviceController::setDeviceLimit(mac, channel, kind, value)`）——只写被编辑的那一个键，另一个键继续走高一级回退，不会把回退值固化到设备上；写入后 `refresh_limits()` 让看板与迷你窗的生效值一起跟上。界面回读走 `DeviceController::limitsFor(mac, channel)`，除 limit / safety / effective 外还给出 `device_limit` / `device_safety` 两个来源标记，两个键都未落盘时该通道标「默认」。

## 实验性输入设备：爪印 V1.1

- GATT 与郊狼相同，**没有独立电量服务**（电量在 `51` 消息里）。
- 连上后立即写 `50` 指令，以 `51` 为回执，无回执重试一次。
- 通知 `51 / 5A / 5B / 5C / D0 / F1` 解析成该实例的 `paw_<MAC 后四位>` 模块数值（旧的单实例模块名 `paw` 只用于旧配置迁移）；内置事件 `button_pressed` / `button_released` 以**实例模块名为模块标识**经 `EventRuntime::register_builtin_events()` 接入事件引擎，插件侧车加载路径未改动。
- 断开顺序固定：`ModuleManager::unregister_module(实例模块名)` → `EventRuntime::unregister_builtin_events(实例模块名)` → 引擎 `remove_module`，随后销毁驱动实例。断开后事件列表里不再出现该实例的事件，重连时重新出现（`tests/input_link_test.cpp` 覆盖注册 → 注销 → 重连三段）。
- `0x0F`（外部电压）的参数映射公式与 `F1` 的 `/2` 取整规则待上游确认，本版只上报原始参数与展示值。
- `47L120100`（V1.0）不可连接，提示需先升级固件。
- **仍需实机确认**：`50` 是否被接受、按键触发时序、电量解析、`D0` 速率。

## 实验性输入设备：灵猫 V1

- 边缘控制传感器，广播名 `47L124000`；GATT 与郊狼相同（服务 `0x180C` / 写 `0x150A` / 通知 `0x150B`），另有电量 `0x180A` / `0x1500`。
- 开机后需连按 5 次开机键才可被搜到。服务发现完成后立即写 `50`（17 字节，`0xD0` 开启气压上报）；协议没有定义 `50` 的回执，以首帧 `D0` 视为生效，无上报重试一次。
- `D0` 按实际长度宽容解析：文档标称 17 字节而示例串只有 15 字节，长度 ≥ 10 字节才取第 8、9 字节 int16 小端 ÷ 100 = kPa，不足 10 字节丢弃并计数。
- 写入该实例 `civet_<MAC 后四位>` 模块的 `pressure`（0.01 kPa 整数）/ `battery` / `raw`；气压 10 Hz 上报按 `app.devices.civet.pressure_epsilon`（缺省 10，即 0.1 kPa）抑制后再落值，避免 10 Hz 持续触发规则求值。阈值是全局键，多台灵猫共用同一抑制口径。
- `66` 指令按「13 字节 → 失败回退 14 字节」两形态给出，两次都失败只记 WARN；本版不做屏幕方向翻转的界面。
- 内置事件 `pressure_rise` / `pressure_drop` 经 `EventRuntime::register_builtin_events()` 接入事件引擎，阈值交给规则配置。
- **仍需实机确认**：`50` 是否被接受（首帧 `D0` 是否等于接受）、`D0` 的实际长度与速率、气压量程与温补（文档未给，本版不做量程假设与温补）、`66` 指令的真实长度形态、电量特征是否可读。

## 输入设备实例名与旧配置迁移

模块名从单实例时代的 `paw` / `civet` 变成按实例生成的 `paw_<MAC 后四位>` / `civet_<MAC 后四位>`（后四位撞车再追加 `_2` / `_3`）。旧配置里对 `paw` / `civet` 的引用不会静默失效，处理方式分两类：

- **自动迁移（`DeviceValueBridge::migrate_legacy_mapping()`，连接第一台实例时执行一次）**：把 `app.plugins.paw` / `app.plugins.civet` 整棵子树（事件映射、通道、波形等键）复制到该实例的模块键 `app.plugins.paw_<后四位>`，随后在旧键下写 `module_migrated_to = 新模块名` 并保存 `user.json`。旧键与旧值原样保留（可手工删除），因此迁移可回溯、可撤销。
  - 只搬一次：旧键已带 `module_migrated_to` 时不再搬给后来连上的设备，第二台同型号不会抢走第一台的映射。
  - 实例已有自己的映射时以实例映射为准，不覆盖用户配置。
  - 配置系统未初始化或写盘失败时只跳过迁移并记日志，不阻断连接。
- **需要人工处理（不自动改）**：规则文件 `config/rules/*.json` 与规则图里的模块数值引用按**数值 ID**（`button` / `accel` / `pressure` / `raw` …）解析，不写模块名，所以旧规则不需要改名也不会失效；真正需要手工改的是**直接按旧模块名写配置或调用接口的地方**——手改的 `user.json`、外部脚本、把模块标识写成 `paw` 的插件侧车，都要换成实例模块名（如 `paw_430C`），否则引用指向一个不存在的模块，表现为该模块数值不落值、事件不出现在事件列表里，日志里伴随「数值注册失败 / 无此模块」的 WARN。

多台同型号同时在线时，同名数值 ID（两台爪印都有 `button`）在规则与公式里不再唯一：`ModuleManager::find_module_by_value_id()` 返回先注册的那一台，本版没有「模块名限定数值」的引用语法，多实例下的规则按第一台求值。

## 实验性输出设备：负鼠 V1

- 帧构造是纯函数：B0 布局与越界静音、B3 的不改语义、B2 两种形态、郊狼帧转负鼠强度字节；驱动把波形进度按每次写入上报，事件波形推进逻辑与郊狼一致。
- B2 的 24 字节与文档标称 20 字节上限冲突，按「先 24 字节写入并等回执 → 失败回退 20 字节 → 再失败关闭屏幕同步」处理；屏幕强度同步失败时二分回退并在界面说明，不影响通道输出。
- `DeviceController` 可注入多个输出设备，默认设备与上下限逻辑保持单一实现。
- **仍需实机确认**：B2 的真实长度形态，以及连接、强度、波形、事件波形与默认设备切换。

## 已知局限

- 默认设备目前只有郊狼一个经过实机验证的候选：负鼠驱动的停旧波形与重发强度分支尚待实机复核。
- **多台设备同时在线只用合成设备（单测桩）验证过**：本仓库没有第二台真实设备，多链路行为（默认设备评选、断开隔离、状态隔离）由 `tests/device_link_test.cpp` 覆盖，真机只验证过单台郊狼。
- **输入设备多实例只用单测验证过**：仓库里没有爪印 / 灵猫实机，实例模块名生成、同后四位消歧、注册 / 注销 / 重连三段由 `tests/input_link_test.cpp` 覆盖，真机行为（两台同型号同时在线、断开后事件列表刷新）尚未实测。
- 「已连接设备 ×N」= 蓝牙已连接链路数（`ble.connectedLinkCount`：输出链路逐台累加 + 已连上的输入设备）+ APP 在线客户端数（`device.appClientCount`）；首页看板设备卡、左下角面板与状态栏三处读同一份口径。逐台明细看设备管理页的「已连接设备」。
- **同一 MAC 的设备键在连续写入后可能只剩后写的那一个**：`app.devices.<MAC>` 段会随写入重建，实测出现过「写完上下限后 `model` 记忆键消失」2 次（另几次两者共存，未能稳定复现）。影响是型号记忆丢失、下次扫描要重新识别；根因在配置合并层（`core/AppConfig` 的动态键子树重建），不在本轮可改边界内，只在此记录。上下限写入本身与其界面回读是正常的：`setDeviceLimit()` 写完补发一次 `limitsChanged`，输入框立即回读新值（离线设备同样适用）。
- 未实现驱动的型号在连接前即被拒绝，界面只给出原因文本，不提供驱动清单。
