# 波形数据结构与 V2 / V3 双数据

> 本文档说明波形模型 `Wave` 的字段、HEX 帧规范、官方内置波形的来源与只读约束、`config/waves/waves.json` 的存储结构，以及发送协议 `app.wave.protocol` 如何选择 V2 / V3 帧。代码实现见 [src/README.md](../src/README.md) 的「wave/ —— 波形」一节与 [include/wave/Wave.h](../include/wave/Wave.h)。

## 一、模型字段

一条波形同时持有 V2 与 V3 两套帧；两套帧各自是权威数据，互不换算。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 波形名，波形库的键；官方内置波形不可改名 |
| `source` | string | 来源：`official`（官方内置资源）或 `user`（用户波形库） |
| `raw` | string | 设计层原始串，形如 `Dungeonlab+pulse:...`；可为空 |
| `sections` | object[] | 段落（起止频率 / 强度），用于再编辑；官方内置波形不带段落 |
| `frames_v2` | string[] | V2 帧序列 |
| `frames_v3` | string[] | V3 帧序列（8 字节 HEX，帧布局见 [include/README.md](../include/README.md) 的「V3 波形帧」） |
| `tags` | string[] | 标签名列表：用名字引用标签库，大小写不敏感去重、已 trim，单条最长 32 个字符（见「八、标签」） |

- 每帧代表 100ms；`duration_ms() = 帧数 × 100`，帧数优先取 `frames_v3`，只有 V3 缺失时才取 `frames_v2`。
- 段落只生成 V3 帧（`Wave::generate_frames`）：编辑器改段落会清空草稿的 V2 帧，此时发送前按协议校验而不做跨版本换算。

## 二、HEX 帧规范

存储与资源中的帧一律满足：大写、无空白、无分隔符、无 `0x` 前缀。

| 版本 | 长度约束 | 校验入口 |
| --- | --- | --- |
| V3 | 固定 16 个十六进制字符（8 字节） | `Wave::normalize_hex_frame(text, 8)` |
| V2 | 偶数长度合法 HEX，帧长不固定 | `Wave::normalize_hex_frame(text, 0)` |

`normalize_hex_frame` 先去掉空白与 `, ; : - _` 分隔符、去掉开头的 `0x`，再校验字符集与长度，返回大写帧；任一环节不合规返回空串。读取侧一律走它，因此手写的 `0x0a 0a0a 0a00 000000` 会被规范成 `0A0A0A0A00000000`，而 `0A0A0A0A0000ZZ00`（非 HEX）、`0A0A0A0A0000000`（15 字符）、`A1010`（奇数长度）被拒绝。

## 三、官方内置波形

官方 16 个波形来自官方开源示例，原样落在只读资源 `assets/waves/official_waves.json`（登记在 `DGLABClient.qrc` 的 `/waves` 前缀下，路径 `qrc:/waves/assets/waves/official_waves.json`），启动时由 `WaveLibrary` 读取，不在 C++ 里手抄帧数组。

| 样例字段 | 内部字段 | 说明 |

加载规则：

- 逐条校验：缺名称、`expectedV2` / `expectedV3` 缺失、任一帧不合规的条目记 `LOG_ERROR` 并跳过，其余条目照常加载（单条坏数据不影响整体）。
- 官方条目 `source = official`，`WaveLibrary::save()` 与 `remove()` 都拒绝它们（不可覆盖、不可删除、不可改名）；从官方波形载入编辑器后另存为新名称即可得到用户副本。标签不受这条限制：官方波形的标签是用户侧叠加数据，可增删，见「八、标签」。
- 官方资源每次启动都读取，用户库文件里的同名条目被官方数据覆盖。
- 旧版内置的占位波形「渐强脉冲」「低频涌动」在加载时移除并记日志；「雨水冲刷」改为官方数据（78 帧），不再由段落推断。

## 四、存储结构

波形库文件 `<wave.path>/waves.json`（默认 `config/waves/waves.json`）：

```json
{
    "version": "1.1",
    "current": { "A": "呼吸", "B": "" },
    "waves": {
        "呼吸": {
            "name": "呼吸",
            "source": "official",
            "raw": "Dungeonlab+pulse:...",
            "sections": [],
            "frames_v2": ["210100", "..."],
            "frames_v3": ["0A0A0A0A00000000", "..."]
        }
    }
}
```

- 官方内置波形同样写入库文件，因此「加载 → 落盘 → 重新加载」后 `raw` / `frames_v2` / `frames_v3` 完全一致；重新加载时仍以资源为准。
- 旧格式（只有 `frames` 的 V3 数组、没有 `frames_v2` / `source`）按 `frames_v3` 读入，`source` 按 `user` 处理，数据不丢。
- 条目里没有任何合规帧时整条跳过并记 `LOG_WARN`；部分帧不合规只丢那些帧。
- 每条波形条目还带 `tags` 数组（标签名列表，无标签写空数组）；官方内置波形的标签在重新加载时由 `tags.json` 的 `official_wave_tags` 段恢复，这里的同名字段不参与读回，见「八、标签」。

## 五、发送协议与缺帧提示

发送协议写在 `user.json` 的 `app.wave.protocol`，取值 `v2` / `v3`，缺省 `v3`；非法取值忽略并按 `v3` 生效。

- 发送路径按协议取对应帧：`WaveLibrary::frames_of(name, protocol)`，`v2` 取 `frames_v2`、`v3` 取 `frames_v3`。
- 目标版本缺帧时**不回落另一版本**、也不发送空数据：`WaveBridge` 写 `lastError`（`波形《X》缺少 V2 帧，未发送` / `当前发送协议为 V2，草稿缺少 V2 帧，未发送`）并记 `LOG_WARN`，界面经既有的「`lastError` 由空转非空 → Toast（danger）」路由提示用户。
- `WaveBridge::waves` 的列表项带 `sendable`（当前协议是否具备帧）、`official`、`frameCountV2` / `frameCountV3`，供界面禁用发送入口。
- 波形预览（`pointsA` / `pointsB` / `amplitudeA` / `amplitudeB`）与事件包络始终取 V3 帧：预览按 V3 的 4×25ms 子单元解析强度与频率。

## 六、测试覆盖

`tests/wave_library_test.cpp`（ctest 目标 `wave_library_test`）逐项验证：

- 16 个官方内置波形全部加载，名称集合与样例一致，且 `raw` 非空、无段落；
- 「呼吸」「潮汐」「雨水冲刷」的 `frames_v2` / `frames_v3` 与样例逐帧相等；
- 存储 round-trip：落盘后重新加载，`raw` / `frames_v2` / `frames_v3` 一致；
- 旧格式只有 `frames` 的条目读入 `frames_v3`；
- 非法帧（长度错误、非 HEX）被拒绝，无合规帧的条目整条跳过；
- 官方波形不可覆盖 / 删除，旧占位波形已移除；
- 协议切换与缺帧不回落。

`tests/wave_import_export_test.cpp`（ctest 目标 `wave_import_export_test`）覆盖导入导出的格式与冲突策略：

- JSON 导出结构：数组形式、四个键齐全、缺 V2 时写空数组并记说明；
- JSON round-trip：16 个官方波形导出后再解析，名称 / `raw` / 两套帧逐条一致，「呼吸」「潮汐」逐帧断言；用户库清空后重新导入仍逐条一致；
- `.pulse` round-trip：导出内容与 `raw` 逐字节一致，读回入库后标记缺帧不可发送；
- 容错：只有 `raw`、只有 V2、只有 V3、别名键 `framesV2` / `framesV3`、非法帧跳过、元素非对象的数组逐条跳过、非法 JSON 报致命错误；
- 冲突三选各一条（覆盖 / 重命名 / 跳过），含官方同名条目拒绝覆盖与自动序号重命名；
- `.pulse` 导出在 `raw` 为空时拒绝且不写文件；只有 `raw` 的条目重新加载后仍在库中。

`tests/wave_zip_test.cpp`（ctest 目标 `wave_zip_test`）覆盖 zip 批量互操作：

- 多波形导出 zip（`raw` → `.pulse`、非法字符替换与去重命名、`index.json` 清单）后重新导入（冲突策略跳过）：波形数量与 `raw` 逐条一致；
- 范围「全部波形」：归档条目数 = 库中波形数 + 1（`index.json`）；
- 归档内混入非 `.pulse` 文件：跳过并计数，`.pulse` 照常导入；目录内条目按文件名入库；损坏的 `index.json` 不影响导入；
- 单个 `.pulse` 内容损坏：只跳过该条；
- 路径穿越条目名（`../`、绝对路径、多级 `..`、盘符）逐条拒绝；
- 解压上限：单文件 5 MiB 与总量 36 MiB 都报错并拒绝整个归档；
- 压缩方式：导出用 deflate（本地头压缩方式 = 8），store（= 0）的归档同样能导入。

`tests/wave_tag_test.cpp`（ctest 目标 `wave_tag_test`）覆盖标签系统：标签规范化、波形标签 round-trip、旧库无 `tags` 字段兼容、导入自动登记、内置标签不可删、删除自定义标签的移除语义、导出含 `tags` 且可再导入，以及官方波形的标签叠加数据（加/删标签后重新加载仍在、删除自定义标签时一并清理、名称与帧仍只读）（逐项见 8.5）。

## 七、导入与导出

接口分层：`wave_io`（[include/wave/WaveImportExport.h](../include/wave/WaveImportExport.h)）只做文本 / 字节与数据结构之间的转换；文件读写与名称冲突判定落在 `WaveLibrary`，入口是 `plan_import()`（按扩展名解析，只解析不写入）、`apply_import()`（按冲突策略写入）、`export_json()`、`export_pulse()` 与 `export_zip()`。界面入口在波形设置页的「导入」/「导出」。

### 7.1 JSON 导出

始终是数组形式（只有一条也包在数组里），每条只写下列四个键：

```json
[
    {
        "name": "呼吸",
        "raw": "Dungeonlab+pulse:35,1,8=0,20,0,1,1/0-1,20-0,40-0,60-0,80-0,100-1,100-1,100-1",
        "expectedV2": ["210100", "210102"],
        "expectedV3": ["0A0A0A0A00000000", "0A0A0A0A14141414"]
    }
]
```

- V2 与 V3 必须同时写出：缺哪一套就写空数组，界面与日志同时标注该波形缺该版本帧。
- 每条还写 `tags` 数组（无标签写空数组）；导出只写这五个键，导入侧忽略不认识的键，后续加字段不需要改解析。
- 范围选「全部波形」时一次导出库中全部波形（含官方内置波形）；官方波形导出的是用户视角的完整数据，因此其标签一并写出。

### 7.2 JSON 导入

- 顶层接受单个波形对象或波形数组。
- 字段名 `expectedV2` / `expectedV3` 是主名，同时接受别名 `framesV2` / `framesV3`、存储字段 `frames_v2` / `frames_v3`，以及旧存储的 `frames`（按 V3 读）。
- `tags` 缺失按空数组处理，别名 `labels` 同样接受；标签逐条规范化（去首尾空白、空串丢弃、大小写不敏感去重、超过 32 个字符丢弃），并自动登记进自定义标签库（见 8.4）。
- 只有 `raw` 的条目照常入库（帧为空，标记为不可发送并给出原因）；只有 `expectedV3` 或只有 `expectedV2` 时只存该套，另一套留空。
- 帧逐条校验：任一条不合规（非 HEX、V3 不是 16 个字符、V2 不是偶数长度）该条整条报错跳过，其它条目照常导入。
- 缺 `name`、或既没有 `raw` 也没有帧的条目跳过并记原因。
- 导入条目的来源一律按用户波形，不会写成官方只读条目。

### 7.3 .pulse 导入导出

- 导出：单波形纯文本，文件名默认 `<波形名>.pulse`，内容就是该波形的 `raw` 原文（不换行包裹、不改写）；`raw` 为空时拒绝导出并给出原因，不产生空文件。
- 导入：读文本 → 校验以 `Dungeonlab+pulse:` 开头 → 名称取文件名（去扩展名），可在冲突弹窗里改写。缺少帧属于正常情况：条目入库后标记「缺少帧、不可发送」，不静默失败。
- 一个 `.pulse` 只装一个波形：批量导出多个波形用下面的 zip，或导出为 JSON。

### 7.4 zip 批量导入导出

- 导出：范围选「全部波形」时可把格式改成 zip，归档内每个波形一个 `<文件名>.pulse`，内容是该波形的 `raw` 原文，与单文件 `.pulse` 完全同构；`raw` 为空的波形不写入归档（汇总里给出一条说明），与单文件导出的拒绝规则一致。
- 文件名规则：波形名里的 `/ \ : * ? " < > |` 与控制字符替换为 `_`，去掉首尾空白与结尾的点，空名回退 `wave`；重名（忽略大小写）依次追加 ` (2)`、` (3)`。
- `index.json` 名称清单：文件名是有损的，因此归档另写一份清单（`name` / `file` / `durationMs` / `frameCountV2` / `frameCountV3`），导入时按清单把名称还原成原始波形名；清单缺失或损坏不影响导入，此时名称取文件名。
- 导入：解压后逐个 `.pulse` 走与单文件 `.pulse` 相同的解析与冲突流程（冲突三选与结果汇总复用），因此 zip 导入的波形同样只有 `raw`、入库后标记「缺少帧、不可发送」。`.pulse` 以外的条目跳过并在汇总里计数（`index.json` 是清单，读后不计入跳过）；单个条目损坏只跳过该条。
- 压缩方式：导出固定用 deflate；读取同时支持 store（不压缩）与 deflate。
- 安全限制（超过即拒绝整个归档并在界面报错，防压缩炸弹）：单条目解压后上限 4 MiB（4194304 字节）、归档解压后总量上限 32 MiB（33554432 字节）、条目数上限 512。
- 路径穿越：条目名以 `/` 或 `\` 开头、带盘符（`C:`）、或任一段为 `..` 的条目一律跳过并记原因。
- 条目名解码优先 UTF-8，非法 UTF-8 时按本地 8 位编码解码（部分压缩工具用 GBK 写文件名）。
- 与官方 App 的互操作：归档里是标准 `.pulse` 文本，官方 App 只要能逐个读取 `.pulse` 即可使用；`index.json` 是附加文件，官方 App 的导入是否会忽略它未验证。反向（官方 App 导出的 zip 直接导入本应用）依赖其压缩方式，store / deflate 均已支持，但**未用官方 App 实际导出的包验证**。

### 7.5 名称冲突

导入前逐条比对库中名称，有重名时弹冲突弹窗，三选一对整批生效：

| 选择 | 行为 |
| --- | --- |
| 覆盖 | 用导入内容替换同名用户波形；同名官方波形拒绝覆盖并跳过（记原因） |
| 重命名 | 单条冲突使用弹窗里改写的新名称（默认建议 `<名称> (2)`）；多条冲突按序号依次生成；新名称仍被占用则继续加序号 |
| 跳过 | 不写入该条，其余条目照常导入 |

结果提示是一条汇总文案（「导入 N 条：新增 a · 覆盖 b · 重命名 c · 跳过 d」），并带跳过与缺帧原因的摘要。

### 7.6 存储侧变化

只有 `raw`、没有任何帧的条目（`.pulse` 导入的波形）在 `waves.json` 里保留；既没有帧也没有 `raw` 的条目才整条跳过。`WaveBridge::waves` 的 `sendable` 仍按当前协议有没有帧计算，这类波形照常显示为不可发送。

## 八、标签

标签是波形上的自由分类，用**名字**引用标签库（不是 id）。所有写入路径都过 `Wave::normalize_tags()`：去首尾空白、丢弃空串与超过 32 个字符的名字、按大小写不敏感去重并保留首次出现的写法，因此 `Sub` 与 `sub` 永远是同一个标签。

### 8.1 两层标签库

| 层 | 位置 | 谁能改 |
| --- | --- | --- |
| 内置标签 | 代码常量 `WaveLibrary::builtin_tags()`，随版本走 | 用户不可增删；本批清单为空，等官方 App 的标签清单补齐后逐条加进常量 |
| 自定义标签 | `<wave.path>/tags.json`（默认 `config/waves/tags.json`） | 用户可增删（内置标签仍不可删） |

```json
{
    "version": 1,
    "tags": ["节奏", "电子"],
    "official_wave_tags": {
        "呼吸": ["节奏"],
        "潮汐": ["电子"]
    }
}
```

- 标签库是独立文件，不进 `user.json`，也不在 `waves.json` 里重复定义；文件缺失或损坏按空库处理并照常启动，首次新增自定义标签时创建。
- 用户波形的标签存在 `waves.json` 每条波形的 `tags` 数组里（见「四、存储结构」）；旧库没有该字段时按空数组读入，不报错。
- 官方内置波形的帧与名称只读（每次启动都由 `assets/waves/official_waves.json` 重建），但**标签是用户侧叠加数据**：单独存在 `tags.json` 的 `official_wave_tags` 段（波形名 → 标签数组，无标签的波形不占键）。加载顺序是「读 `tags.json` 标签库 → 读 `waves.json` → 重建官方资源 → 应用 `official_wave_tags`」，因此重新加载官方资源后标签照样恢复；没有任何自定义标签、也没给官方波形打过标签时不写这一段（空对象）。
- 叠加数据同样过 `Wave::normalize_tags()`：手工编辑 `official_wave_tags` 里的非法项（空串、超长、仅大小写不同的重复、名字已不存在的官方波形）被丢弃，不影响启动。

### 8.2 界面与写入路径

- 波形设置页「波形标签」卡片分三块：内置标签（锁标识，只展示）、自定义标签（语义色，只展示）、波形列表（每个波形条目的标签显示在波形名上方，无标签时整行不占位）。官方波形条目照常显示「内置只读」标识（只描述帧与名称不可改），「编辑标签」不再置灰——16 个官方波形和用户波形一样能勾选、新建、取消标签。
- 「编辑标签」打开标签选择器（`dialogs/WaveTagDialog.qml`）：勾选即写入该波形，取消勾选只从波形上移除、**不动标签库**；也可输入新名字「新建并勾选」，新建即入库。
- 新名字重复（大小写不同）沿用库里已有的写法，不产生第二条；空名字忽略；超过 32 个字符拒绝并弹 Toast 说明。
- 标签名用名字引用，删除标签库条目不会留下悬空 id 问题，因为删除时会同时清理引用（见 8.3）。

### 8.3 删除语义

| 操作 | 标签库条目 | 波形上的标签 |
| --- | --- | --- |
| 波形上取消勾选某个标签 | 保留 | 从该波形移除 |
| 删除自定义标签（无波形在用） | 删除 | 无变化 |
| 删除自定义标签（仍有 N 个波形在用） | 先弹「N 个波形正在使用该标签，仍要删除吗」，确认后删除 | 从这 N 个波形上一并移除 |
| 官方波形上取消勾选某个标签 | 保留 | 从该官方波形的叠加数据里移除，`official_wave_tags` 同步改写 |
| 删除自定义标签（官方波形在用） | 删除 | 官方波形上的引用一并清理，叠加数据里不留这个名字 |
| 删除波形 | 保留 | 随波形消失 |
| 删除内置标签 | 拒绝并提示 | 无变化 |

删除自定义标签时之所以连引用一起清掉：界面上的标签按名字到库里查（用量、勾选态、是否内置），留下只存在于波形上的名字会让选择器出现无法取消的条目，也让「标签库」与「波形上的标签」两处说法不一致。

用量（`tag_usage`）与「未入库但被引用的标签」（`all_tags`）都按库里的波形条目统计，官方波形同样是条目，因此给官方波形打标签后用量会 +1，选择器里显示「N 个波形在用」。

### 8.4 导入时自动登记

- JSON 导入里出现、且不属于内置标签的名字，自动写入 `tags.json`（大小写不敏感去重）；只有真正写进库的波形上的标签才登记。
- `.pulse` 与 zip 归档不带标签，不受影响；导入的标签本身不影响四个既有键的语义。

### 8.5 测试覆盖

`tests/wave_tag_test.cpp`（ctest 目标 `wave_tag_test`，全部用例在临时目录内构造）：

- 标签规范化：trim / 空串忽略 / 大小写不敏感去重 / 超过 32 个字符拒绝；
- 波形标签 round-trip：写盘再读回一致，`waves.json` 的条目里出现 `tags` 数组；
- 旧 `waves.json`（条目无 `tags` 字段）读入不报错，标签按空处理；
- JSON 导入自动登记：自定义标签进 `tags.json`，内置标签不入库，大小写重名不重复；
- 内置标签不可删（注入内置标签后 `remove_custom_tag` 返回 -1 并给出原因）；
- 删除自定义标签：使用中的波形一并移除，标签库条目同时删除；只从波形上移除不影响标签库；
- JSON 导出含 `tags`，导出的文件删掉波形后能再导入并逐条还原标签；
- 官方波形加标签：写进 `tags.json` 的 `official_wave_tags`，重新加载后仍在，`tag_usage` 计入官方波形，导出带标签，帧数不变；
- 官方波形上取消勾选：只从该波形移除，标签库条目保留，重新加载后不复活；
- 删除自定义标签时官方波形上的引用一并清理，重新加载后不复活；
- 官方波形的名称与帧仍不可改：同名保存与删除都被拒绝，重新加载后帧与资源逐帧一致。
